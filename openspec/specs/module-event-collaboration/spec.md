# module-event-collaboration Specification

## Purpose

`masterdata`がカテゴリを無効化する前に、`expense`が未処理経費からの参照を検査し、モジュールの依存方向を維持したまま同期イベントによる業務拒否とトランザクションのロールバック伝播を検証する。

## Requirements

### Requirement: カテゴリ無効化前に値のみの同期イベントを発行する

`masterdata`はカテゴリを無効化する前に、対象カテゴリの識別子だけを含み、ドメインモデルを含まない同期イベントを発行しなければならない（`SHALL`）。

#### Scenario: カテゴリ無効化の開始

- **WHEN** 有効なカテゴリの無効化を要求する
- **THEN** 対象カテゴリを識別する同期イベントが1回発行される
- **AND** 受信側の処理が完了するまでカテゴリの無効化は確定しない

### Requirement: expenseが自身のデータから未処理経費の参照を検査する

`expense`はカテゴリ無効化イベントを受信したとき、自身が所有する経費データだけを使用して、対象カテゴリを参照するDraftまたはSubmitted状態の経費申請が存在するか検査しなければならない（`SHALL`）。

#### Scenario: 未処理経費から参照されていないカテゴリ

- **WHEN** 対象カテゴリを参照するDraftまたはSubmitted状態の経費申請が存在しない
- **THEN** `expense`はカテゴリの無効化を許可する

#### Scenario: 未処理経費から参照されているカテゴリ

- **WHEN** 対象カテゴリを参照するDraftまたはSubmitted状態の経費申請が存在する
- **THEN** `expense`はカテゴリの無効化を拒否する
- **AND** 拒否理由を呼出元へ伝播する

### Requirement: 参照検査の拒否はカテゴリ無効化をロールバックする

同期イベントの受信処理はカテゴリ無効化と同じトランザクションに参加し、`expense`による拒否が発生した場合はカテゴリ状態を変更してはならない（`SHALL`）。

#### Scenario: 参照検査が成功する

- **WHEN** 未処理経費から参照されていないカテゴリを無効化する
- **THEN** カテゴリは無効状態でコミットされる

#### Scenario: 参照検査が拒否する

- **WHEN** 未処理経費から参照されているカテゴリの無効化を試みる
- **THEN** 無効化操作は失敗する
- **AND** カテゴリは有効状態のまま維持される
